# Вход курьера без PIN — по открытой явке iiko

Дата: 2026-07-06. Статус: согласовано с заказчиком (охват, сессия, защита, филиал, фильтр ролей).

## Суть

В Telegram-аппе курьера PIN заменяется выбором своего имени из списка людей,
у которых **сегодня открыта явка** в iiko на филиале «Гейдар Алиева».
Два тапа, ноль ввода. iiko — только чтение. Кухонный KDS (вход по PIN) не трогаем.

Логика допуска: открытая сегодня явка = человек реально сегодня работает здесь.

## Подтверждено разведкой на проде (RMS 6.3.2008)

- `GET /resto/api/employees/attendance/byDepartment/{depCode}?from=YYYY-MM-DD&to=YYYY-MM-DD`
  работает (200, XML `<attendances>`), депо адресуется **кодом** (`10ASTKBN`), не UUID.
- Поля: `employeeId`, `dateFrom`, `dateTo` (отсутствует → явка открыта), `departmentId`.
- В выборку попадают и незакрытые хвосты прошлых лет (реально видели 5 шт. с 2024–2025),
  поэтому фильтр строго: **`dateTo` пуст И `dateFrom` = сегодняшний локальный день (+5)**.
- Параметры `from`/`to` обязательны (без них 400).

## Решения заказчика

| Вопрос | Решение |
|---|---|
| Охват | Только Telegram-апп курьера; PIN на KDS остаётся |
| Филиал | Только «Гейдар Алиева», шага выбора филиала нет |
| Сессия | Живёт, пока явка открыта; явка закрыта / новый день → снова список имён |
| Чужое имя | Метка «занято»: предупредить, но пустить |

## Фильтр ролей (исключающий, по mainRoleCode)

Скрыть: `CS1` (кассир), `CO1` (повар), `СуШеф`, `СУШ`, `СЭКСПО12`, `СЭКСПО13` (сушисты),
`ПИЦЦ`, `ПЭКСПО13` (пиццеристы). Всех остальных показывать
(КР, КЭКСПО20, MN0, УПРЭКСПО, Администратор, WR1, DW1, ADM/ADM2, opeCC, Бух, GBUH, МАРКЕТ…).

## Архитектура

### Бэкенд

1. **`rms.py`**: в `_parse_employees_full()` добавить `id` сотрудника (нужен джойн с явками).
   Новая функция `open_attendances_today()`:
   - явки `byDepartment/{settings.branch_code}` за сегодня (локальный день, +5);
   - фильтр «открыта и начата сегодня», дедуп по `employeeId` (явки бывают задвоены);
   - джойн с сотрудниками из существующего кэша `_employees_and_departments_cached()`
     (имя, `mainRoleCode`); исключить роли из списка выше, а также `deleted` / `is_employee=false`;
   - кэш результата ~60с — не жжём слот лицензии RMS.
2. **API** (`api.py`):
   - `GET /tg/shift-employees` → `[{employee_id, name, role, busy}]`,
     `busy` = сегодня этого сотрудника уже выбрал другой Telegram-аккаунт;
   - `POST /tg/claim {initData, employee_id}` → проверить подпись initData (как в текущем
     `/tg/link`), проверить, что явка сотрудника всё ещё открыта сегодня → сохранить привязку
     → ответ в формате текущего `/tg/link` (`name/role/branch_code/org_id/courier_code`).
     `courier_code` = `code` сотрудника из RMS — ничего ниже по течению
     (`/tg/my-orders`, назначение заказов, статистика) не меняется.
3. **Привязка**: переиспользуем модель `TelegramLink`, добавляем колонки
   `employee_id` (UUID из RMS) и `claimed_on` (локальная дата входа).
   `/tg/auth` на открытие аппа: привязка есть, `claimed_on` = сегодня И явка ещё
   открыта → сразу в заказы; иначе → список имён (старые PIN-привязки без
   `claimed_on` считаются протухшими — один раз выберут имя заново).
   «Занято» — `employee_id` за сегодня уже привязан к другому `telegram_id`.
   `/tg/link` (PIN) удаляем вместе с фазой `pin` на фронте.

### Фронт (`TgCourier.jsx`)

Фаза `pin` заменяется фазой `pick`:
- список имён (имя + должность), тап → `POST /tg/claim` → фаза `orders`;
- у занятых имён пометка; при тапе — предупреждение «под этим именем уже вошли», кнопка «всё равно войти»;
- кнопка «Обновить» + подсказка «Нет твоего имени? Попроси кассира открыть смену в iiko»;
- пустой список — та же подсказка.

## Ошибки и края

- RMS недоступен → фронту 503 и «iiko недоступен, попробуй позже» (не пустой список).
- Явка закрылась между показом списка и тапом → claim вернёт 409, фронт обновит список.
- Двойные явки одного человека → одна строка (дедуп).
- Ночную смену «начата вчера, ещё открыта» не показываем — филиал не 24/7, это хвост.
- У сотрудника нет `code` в RMS → войти сможет, но назначенные заказы по коду
  не сматчатся (так же, как сегодня: без PIN он вообще не мог войти).
