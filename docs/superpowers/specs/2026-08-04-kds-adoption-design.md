# Saya KDS: adoption — чтобы системой пользовались

Дата: 2026-08-04
Статус: дизайн одобрен, готов к плану реализации

## Проблема

Персонал не пользуется KDS. Заказы готовятся и отдаются, но отметки на экране
не ставят — ни повара, ни курьеры. Названная заказчиком причина: **нет
последствий**. Не отметил — ничего не произошло.

Почему курьеры не переходят в TG-апп — неизвестно. Заказчик: «в моих глазах всё
отлично, но не знаю». Это само по себе часть проблемы: **мы не измеряем
использование**, поэтому чиним вслепую.

Дополнительное требование заказчика: звук о новом заказе должен быть таким,
что его **нельзя отключить**.

## Что уже подтверждено чтением кода

Эти факты определили дизайн:

- `frontend/src/lib/sound.js:16` — `isSoundOn()` возвращает
  `localStorage.getItem("saya_sound_on") === "1"`, то есть **звук по умолчанию
  выключен**. В `ScreenHeader` есть колокольчик-тоггл, которым его глушат.
  `unlockAudio()` требует тапа после каждой перезагрузки вкладки.
- `backend/app/alerts.py:83` — просрочка ищется по условию
  `station_accepted_at is not None and station_ready_at is None`. Но
  `station_accepted_at` до нажатия «Готово» всегда `None`
  (`backend/app/api.py:369` проставляет его задним числом уже в момент
  «Готово»). **Условие не выполняется никогда — алерт о просрочке не
  срабатывал ни разу.** Плюс сам модуль отключён (`ALERTS_INTERVAL_SECONDS=0`).
- `backend/app/api.py:395` — `POST /items/{id}/revert` уже существует, откат
  готовности на бэкенде есть. Не хватает только кнопки на кухонном экране.
- Шага «Принял» в UI больше нет (`api.py:367`) — one-tap готовность уже
  реализована.
- `backend/app/models.py:87` — у `OrderEvent` уже есть `actor_code`,
  `actor_name`, `item_id`. Телеметрия использования считается по ним, новая
  таблица событий не нужна.
- `backend/app/api.py` — 2062 строки. Новые ручки в него не добавляем.
- Кухонный экран — **планшет Android в браузере**. Это определяет решения по
  звуку и wake lock.

## Подход

Три фазы строго в этом порядке. Порядок и есть суть дизайна.

**Фаза 0 — увидеть.** Нельзя чинить то, что не измеряешь, и нельзя доказать,
что «последствия» сработали, без цифры «до».

**Фаза 1 — убрать трение.** К моменту включения блокировки экран должен быть
быстрее бумажки. Блокировка поверх неудобного интерфейса = кухня встала и
систему выключили навсегда.

**Фаза 2 — включить последствия.** По нарастающей, каждый механизм за своим
флагом, жёсткая блокировка — последней.

Отклонённые альтернативы:

- *Только кнут* (все последствия сразу): заказчик сам не знает, почему не
  переходят. Включать блокировку вслепую — риск остановить кухню в первый пик.
- *Только пряник* (UX без последствий): не закрывает названную причину, месяц
  работы вхолостую.

## Фаза 0 — видимость и звук

### Неубиваемый звук

Звук перестаёт быть настройкой и становится свойством системы.

1. **Удалить `saya_sound_on` и колокольчик-тоггл целиком.** Не «по умолчанию
   включён» — понятия «выключить» не существует. При загрузке приложения
   выполняется одноразовая миграция, стирающая ключ из `localStorage`: иначе
   планшеты, где звук уже выключили, останутся немыми навсегда.
2. **`unlockAudio()` вешается на логин оператора** — гарантированный тап, после
   которого `AudioContext` жив всю смену.
3. **Watchdog каждые 5 секунд** проверяет `ctx.state`. Если не `running` —
   компонент `AudioGuard` рисует полноэкранную красную плашку «🔇 ЗВУК НЕ
   РАБОТАЕТ — КОСНИСЬ ЭКРАНА» поверх заказов; заказы под ней не видны и не
   кликаются. Работать молча технически невозможно.
4. **Screen Wake Lock API** — планшет не гаснет, таймеры вкладки не
   троттлятся. Лок переподнимается на `visibilitychange`. Если API не
   поддержан — работаем без него и сообщаем это в хартбите.
5. **Тишину видит управляющий.** Хартбит передаёт `audio_ok`. Если экран стоит
   без рабочего звука дольше 3 минут — управляющему в TG уходит «🔇 Экран
   „Роллы" без звука 12 мин». Заглушить всё ещё физически возможно, но это
   перестаёт быть бесплатным.
6. **Планшет переводится в Fully Kiosk Browser**: автостарт, блокировка кнопок
   громкости, перезапуск при падении, экран всегда включён. Из браузера
   системную громкость Android защитить нельзя — это единственный способ
   закрыть последнюю дыру. Организационный пункт, не код.

### Телеметрия использования

- **`ScreenHeartbeat`** (новая таблица): `screen_id`, `station`, `org_id`,
  `operator_code`, `operator_name`, `audio_ok`, `wake_lock_ok`, `last_seen`.
  Экран шлёт `POST /api/screens/heartbeat` раз в 30 секунд. Отвечает на
  вопрос, который сейчас задать невозможно: «экран вообще был открыт?» —
  то есть отличает «не отметил» от «планшет лежал выключенным».
- **`GET /api/analytics/adoption?from&to`** — покрытие KDS: по каждому
  сотруднику и каждому дню, сколько позиций получили отметку через экран
  против того, сколько закрылось в iiko без единого касания. Считается по
  наличию `OrderEvent` с непустым актором для позиции — миграции схемы не
  требует.
- **Вкладка в `Analytics.jsx`**: крупная цифра «% покрытия KDS за сегодня»,
  ниже разбивка по людям и станциям.

Фаза 0 выкатывается **и работает неделю в одиночку**, без Фаз 1 и 2, чтобы
получить базовую линию для сравнения.

## Фаза 1 — убрать трение

- **Хит-зона.** One-tap готовность уже есть; увеличиваем зону нажатия до всей
  строки, минимум 64px по высоте — под мокрые руки и локоть.
- **Undo на кухонном экране.** 30 секунд после тапа строка держит кнопку
  «Вернуть», дёргающую существующий `POST /items/{id}/revert`. Дальше откат
  только через сборщика. Обязателен в одном пакете с блокировкой из Фазы 2:
  ошибочный тап не должен быть необратимым.
- **All-day counts** (практика Toast/Simphony). Шапка станции показывает свод
  по всей очереди: «Филадельфия ×7 · Калифорния ×4 · Пицца 4 сыра ×2». Повар
  готовит партией вместо беготни по карточкам. Самая дешёвая фича списка и
  самая заметная для повара — основной пряник.
- **Офлайн-режим.** Тапы копятся в очереди в `localStorage` и досылаются при
  возврате связи. В шапке честный индикатор: «нет связи, 3 отметки в очереди».
  Сейчас отвал вайфая полностью ослепляет кухню — железная причина вернуться к
  бумаге.
- **Видимый приоритет.** Сортировка по срочности уже есть (`orderUrgency`);
  добавляем крупный порядковый номер на карточке, чтобы с двух метров было
  понятно, что брать следующим.

## Фаза 2 — последствия

Каждый механизм за отдельным флагом в таблице `Setting`, гасится из админки за
минуту без деплоя.

### 1. Эскалация в TG

Сначала чиним баг: просрочка считается от `order.created_at`, а не от
`station_accepted_at`. Порог аномалии (`< 60с` между accept и ready) при этом
теряет смысл, поскольку accept равен created_at — переносим детекцию аномалии
на «готово раньше N секунд от появления заказа», N = 60.

Лестница:

- **5 мин** без отметки — карточка на экране станции пульсирует красным;
- **10 мин** — управляющему в TG: «⚠️ №1423, Роллы, 11 мин без отметки. На
  станции: Азер»;
- **20 мин** — повтор с добавлением данных хартбита: был ли экран открыт.

Отдельный алерт: **на станции никто не залогинен, а заказы идут**. Это и есть
«не пользуются» в чистом виде, и сейчас оно полностью невидимо.

Дедупликация переезжает из памяти (`alerts.py:23`, `_alerted: set`) в БД —
иначе рестарт Render зальёт управляющего повторами.

### 2. Живой рейтинг смены

Полоса внизу кухонного экрана, всегда на виду: имя — сделано за смену —
среднее время — просрочки, отсортировано по среднему времени. Обновляется в
реальном времени. Социальное давление без участия начальства.

### 3. Отчёт по итогам смены

Управляющему в TG при закрытии смены: покрытие KDS в процентах, по каждому
сотруднику сколько отметил и сколько прошло мимо, среднее время, просрочки,
сравнение со вчера. Документ, по которому можно вести разговор о премии.

### 4. Жёсткая блокировка (включается последней)

Сборщик не может отдать заказ, пока кухня не отметила готовность; курьер не
видит заказ в «готов к выдаче».

Обязательные страховки:

- **Обход по PIN управляющего** с записью `block_override` в `OrderEvent` —
  кто и когда обошёл. Без этого один баг останавливает ресторан.
- **Флаг включается только после того, как телеметрия Фазы 0 покажет покрытие
  выше 80%.** Блокировать поток, когда экраном пользуется половина смены —
  гарантированный бунт.
- **При недоступном бэкенде блокировка снимается автоматически.** Если сервер
  лёг, кухня работает.

Порядок включения: механизм 1 → неделя → механизмы 2 и 3 → неделя →
механизм 4. Каждый шаг сверяется по цифре покрытия.

## Архитектура

### Данные

- **`ScreenHeartbeat`** (новая) — присутствие и здоровье экранов, поля выше.
- **`Setting`** (новая, key/value) — фича-флаги в БД, а не в env, чтобы
  гасились без деплоя.
- **`OrderEvent`** — не меняется. Новые значения `type`: `item_ready`,
  `item_recall`, `block_override`.

### Модули

`backend/app/api.py` — 2062 строки, новые ручки туда не добавляем. Отдельными
роутерами:

- `app/heartbeat.py` — приём и чтение хартбитов экранов;
- `app/adoption.py` — расчёт покрытия KDS;
- `app/shift_report.py` — сводка по смене;
- `app/flags.py` — чтение и запись фича-флагов;
- `app/alerts.py` — расширяем существующий: лестница, имена, дедуп в БД.

Фронтенд:

- `lib/sound.js` — переписывается (без тоггла, с watchdog);
- `lib/wakelock.js` — новый;
- `lib/offlineQueue.js` — новый;
- `components/AudioGuard.jsx`, `components/AllDayCounts.jsx`,
  `components/ShiftBoard.jsx` — новые;
- `components/KitchenItemRow.jsx` — хит-зона и кнопка «Вернуть»;
- `components/ScreenHeader.jsx` — убрать колокольчик, добавить индикатор
  офлайн-очереди;
- `screens/Analytics.jsx` — вкладка покрытия.

### Обработка ошибок

- Офлайн-очередь шлёт **идемпотентно** по ключу `(item_id, action)` — повторная
  отправка безопасна.
- Падение Telegram не роняет цикл алертов (уже реализовано).
- Wake Lock не поддержан — работаем без него, факт уходит в хартбит.
- Блокировка при недоступном бэкенде снимается автоматически.

## Тестирование

Бэкенд (pytest, каталог `backend/tests` уже есть):

- расчёт покрытия KDS на подготовленном наборе `OrderEvent`;
- лестница эскалации: срабатывание на 5/10/20 минутах от `created_at`;
- дедупликация алертов переживает рестарт процесса;
- фича-флаги включают и выключают механизмы;
- алерт «на станции никто не залогинен».

Фронтенд:

- офлайн-очередь: накопление, досылка, идемпотентность при дубле;
- миграция звука: старое `"0"` в `localStorage` не оставляет экран немым;
- watchdog показывает `AudioGuard` при suspended-контексте.

Ручной чек-лист на планшете:

- перезагрузка вкладки — звук работает без ручного включения;
- отвал вайфая на 5 минут — отметки не потеряны;
- попытка заглушить звук — появляется плашка и уходит алерт управляющему;
- экран не гаснет за смену.

## Метрика успеха

**Покрытие KDS выше 80%** — доля позиций, получивших отметку через экран, от
всех приготовленных. Замер: базовая линия после недели Фазы 0, затем
понедельные срезы после каждого включённого механизма Фазы 2.

## Сознательно не входит в этот проект

- **JIT-фаер по ETA курьера** — наше уникальное преимущество (кухня и курьеры в
  одной системе, чего нет у Toast и Square), но это отдельный следующий проект.
- **ML-модель времени приготовления, coursing, throttling** — бесполезны, пока
  в экран не смотрят.
- **Компьютерное зрение на сборке, прогноз производства** — не наш масштаб
  сейчас.
