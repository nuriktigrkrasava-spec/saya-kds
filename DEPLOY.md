# Деплой «Saya KDS» на Render (пошагово, без знаний программирования)

Цель: запустить проект в облаке так, чтобы один веб-адрес (URL) отдавал и API,
и сам сайт (экран кухни), а данные хранились в облачной базе PostgreSQL.

Всё настроено через файл `render.yaml` в корне репозитория — Render сам прочитает
его и создаст нужные сервисы. Вам останется только вставить секреты и сделать
пару действий после первого запуска.

---

## Шаг 1. Залить проект на GitHub

1. Создайте бесплатный аккаунт на https://github.com (если ещё нет).
2. Создайте новый пустой репозиторий, например `saya-kds` (можно private).
3. Загрузите туда код проекта. Если репозиторий уже подключён, просто отправьте
   ветку `phase1-backend-ingest` на GitHub (это та ветка, с которой работает
   деплой — она прописана в `render.yaml`).

Важно: файл `.env` с секретами на GitHub попадать НЕ должен (он в `.gitignore`).
Секреты мы введём вручную в дашборде Render на Шаге 3.

---

## Шаг 2. Создать сервисы на Render через Blueprint

1. Зарегистрируйтесь на https://render.com (можно войти через GitHub).
2. Нажмите **New** (в правом верхнем углу) → **Blueprint**.
3. Выберите ваш репозиторий `saya-kds` и ветку `phase1-backend-ingest`.
4. Render найдёт файл `render.yaml` и покажет, что будет создано:
   - веб-сервис **saya-kds** (это и API, и сайт);
   - база данных **saya-kds-db** (PostgreSQL).
5. Нажмите **Apply** / **Create**. Render начнёт создавать базу и сервис.

На этом этапе сборка может «упасть» или ждать — это нормально, потому что мы ещё
не заполнили секреты и адрес базы. Делаем это на следующих шагах.

---

## Шаг 3. Заполнить секреты (переменные окружения)

Откройте веб-сервис **saya-kds** → вкладка **Environment** (Переменные окружения).
Там будет список переменных, которые надо заполнить. Вот что куда вставлять:

| Переменная           | Что это и где взять                                                                 |
|----------------------|------------------------------------------------------------------------------------|
| `CLOUD_API_LOGIN`    | apiLogin из личного кабинета **iikoWeb** (раздел интеграций / Cloud API).           |
| `RMS_BASE`           | Базовый адрес вашего iiko RMS-сервера (например `https://ваш-сервер:443`).          |
| `RMS_LOGIN`          | Логин пользователя iiko RMS (с правами API).                                        |
| `RMS_PASSWORD`       | Пароль этого пользователя iiko RMS.                                                 |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота. Получить у **@BotFather**: команда `/newbot`, придумать имя — он выдаст токен вида `1234567:AAâ€¦`. |
| `WEBHOOK_SECRET`     | Придумайте сами длинную случайную строку (минимум 32 символа, буквы+цифры). Это «пароль» для приёма данных от iiko. Запишите его — пригодится на Шаге 5. |
| `JWT_SECRET`         | Тоже придумайте сами длинную случайную строку (минимум 32 символа). Используется для входа в админку. |

Совет по генерации случайной строки: можно нажать любые 40+ символов на клавиатуре,
или воспользоваться любым онлайн-генератором паролей (длина 40, буквы+цифры).

Не нажимайте пока Save Changes до Шага 4 — добавим ещё `DATABASE_URL`.

---

## Шаг 4. Подключить базу данных (ВАЖНО — про `+asyncpg`)

Приложение использует «асинхронный» драйвер базы, поэтому адрес базы должен
начинаться с **`postgresql+asyncpg://`**, а НЕ с `postgres://`.
Render по умолчанию выдаёт адрес в формате `postgres://...` — его нужно слегка
переписать. Делается это один раз:

1. Откройте базу **saya-kds-db** → найдите поле **Internal Database URL**
   (внутренний адрес — он быстрее и бесплатен для трафика между сервисами).
   Скопируйте его. Он выглядит примерно так:
   `postgres://saya_kds:ПАРОЛЬ@dpg-xxxx-a/saya_kds`
2. Замените в начале `postgres://` на `postgresql+asyncpg://`.
   Должно получиться:
   `postgresql+asyncpg://saya_kds:ПАРОЛЬ@dpg-xxxx-a/saya_kds`
3. Вернитесь в веб-сервис **saya-kds** → **Environment** → переменная
   `DATABASE_URL` → вставьте туда исправленный адрес (с `+asyncpg`).
4. Нажмите **Save Changes**. Render автоматически пересоберёт и перезапустит сервис.

Почему так: в `render.yaml` переменная `DATABASE_URL` помечена как ручная
(`sync: false`) именно для того, чтобы вы вставили правильную форму с `+asyncpg`.
Автоматическая подстановка дала бы неподходящий `postgres://`.

Таблицы в базе создаются сами при первом запуске — отдельных «миграций»
запускать не нужно.

---

## Шаг 5. Дождаться деплоя и открыть сайт

1. На странице сервиса **saya-kds** дождитесь статуса **Live** (зелёный).
   Если сборка падает — откройте вкладку **Logs** и посмотрите сообщение
   (чаще всего это незаполненный секрет или неправильный `DATABASE_URL`).
2. Вверху страницы будет адрес вида `https://saya-kds.onrender.com`
   (или ваш — назовём его дальше `https://ВАШ-ДОМЕН`).
3. Проверка «живости»: откройте `https://ВАШ-ДОМЕН/health` — должен прийти
   короткий ответ-«ок».
4. Откройте просто `https://ВАШ-ДОМЕН` — должен загрузиться сам интерфейс.

---

## Шаг 6. ОБЯЗАТЕЛЬНО после деплоя — подключить iiko и Telegram

### 6.1. Зарегистрировать webhook iiko (чтобы заказы прилетали в систему)

Системе нужно сообщить iiko, куда присылать события. Адрес для webhook:

```
https://ВАШ-ДОМЕН/webhooks/iiko/cloud?key=ВАШ_WEBHOOK_SECRET
```

Подставьте сюда:
- `ВАШ-ДОМЕН` — адрес сервиса из Шага 5;
- `ВАШ_WEBHOOK_SECRET` — ту самую строку, что вы задали в переменной
  `WEBHOOK_SECRET` на Шаге 3.

Как зарегистрировать этот адрес в iiko: в личном кабинете iikoWeb / iiko Cloud
API в разделе настроек уведомлений (webhooks / notifications) укажите этот URL
как адрес получения событий. Если в вашей версии iiko регистрация webhook
делается через запрос к API — передайте этот же URL технической поддержке iiko
или вашему интегратору, попросив «подписать организацию на webhook по этому
адресу». Главное — чтобы iiko стучался именно по адресу выше, вместе с `?key=...`.

### 6.2. Настроить кнопку Telegram-бота

Чтобы кнопка/ссылка бота открывала ваш интерфейс, она должна вести на:

```
https://ВАШ-ДОМЕН/tg
```

Где это указать: у @BotFather командой `/setmenubutton` (кнопка меню бота) —
выберите бота и задайте этот URL как Web App / ссылку кнопки. Так пользователь,
нажав кнопку в боте, попадёт на страницу `/tg` вашего сервиса.

## Важные замечания

- **Платный инстанс обязателен для постоянной работы.** На бесплатном плане Render
  сервис «засыпает» при простое и просыпается с задержкой, а соединения теряются —
  для кухни это недопустимо. В `render.yaml` уже выбран платный план (`starter`
  для сервиса и `basic-256mb` для базы); при желании поменяйте на нужный тариф.
- **`DATABASE_URL` всегда в форме `postgresql+asyncpg://...`** (см. Шаг 4).
  Если в логах ошибка про драйвер базы или «dialect/driver» — почти наверняка
  забыли заменить `postgres://` на `postgresql+asyncpg://`.
- **Секреты не храните в репозитории.** Они вводятся только в дашборде Render.
- При смене любого секрета Render сам перезапустит сервис после **Save Changes**.

## Что под капотом (справочно)

- Сборка (buildCommand): `cd frontend && npm ci && npm run build && cd ../backend && pip install -e .`
  — собирает сайт в `frontend/dist`, затем ставит Python-зависимости бэкенда.
- Запуск (startCommand): `cd backend && uvicorn app.main:app --host 0.0.0.0 --port $PORT`
  — поднимает FastAPI; он же отдаёт собранный сайт из `frontend/dist`.
- Проверка здоровья: `/health`.
- Всё это описано в `render.yaml`. Вспомогательный скрипт сборки —
  `backend/build.sh` (для ручного запуска; на сам деплой не влияет).
